# Kizuna Hooks — 约束层方法论

> 来源：Kizuna Harness（自 Claude Code 源码逆向重建的约束体系）。本技能让 DSH 继承同一套治理规则。

## 10 事件检查清单

### 1. SessionStart（会话开始）【L1】
- 查强制清单（铁律）→ 若存在必须加载
- 有活动项目则查项目快照与用户偏好
- 精选记忆 ≤5 条注入上下文

### 2. UserPromptSubmit（用户消息）【L2】
- 模糊指代澄清：这个/那个/它 → 主动确认
- 提取用户意图后再规划行动

### 3. PreToolUse（每次工具调用前）【L1】
- 授权检查：破坏性操作（删/改/推送）先确认
- 临时文件只用 /data/local/tmp/ 并事后清理
- 危险命令检查（rm -rf /、格式化等）

### 4. PostToolUse（工具成功后）【L2】
- 产出验证 + 副作用检查
- 重要产出 → 记入项目快照

### 5. PostToolUseFailure（工具失败时）【L2】
- 捕获上下文：错误 + 操作 + 输入输出
- 同一操作连续失败 3 次 → 停止并建议回退方案

### 6. PermissionRequest（敏感操作）【L1】
- 展示完整待操作清单
- 分级：自由操作→直接执行 / 需确认→列清单 / 高风险→询问用户

### 7. Stop（回复生成前）【L1】
- 反幻觉自查：所有引用必须真实存在
- 重要任务后自我批判：是否有更优路径/遗漏资源
- Token 简报：使用超 60% 提醒用户

### 8. PreMemoryWrite（写入记忆前）【L2】
- 自动分类：标题前缀 → 对应文件夹
- 去重：已有条目用 update 而非 create

### 9. PreCompact（上下文压缩前）【L1】
- 保留三类锚点：铁律 + 项目状态 + 待办清单

### 10. 强制力三级分层
- L1 确定性：代码/文件/安全规则，必须执行
- L2 引导性：流程规范，强烈建议
- L3 参考性：最佳实践，按需参考

## 使用方式
- 触发时机：任何工具调用、消息接收、回复生成、记忆写入、会话生命周期事件
- 本技能为方法论索引，详细规则以用户提供的具体清单为准
