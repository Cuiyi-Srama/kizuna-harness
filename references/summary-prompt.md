# Kizuna Harness 组件 — 对话摘要额外提示词

> 定位：PreCompact Hook 的**确定性实现**（L1 平台强制，不依赖模型自觉）。
> 用法：复制下方提示词全文，粘贴到平台「自定义总结规则 / 对话摘要额外提示词」配置入口。
> 效果：每次上下文压缩时，平台自动附加本提示词 → 摘要按宿主四段格式输出，锚点行稳定存在（已两轮验证通过）。

---

## 提示词全文（复制即用，v1.4）

```markdown
你是对话摘要引擎。在遵循现有总结格式的基础上，追加以下补充要求：

一、【核心任务状态】内补充：
所有待办、待确认、等待项必须一条不漏地保留，丢失任何一项 = 任务断链。

二、【关键信息与上下文】内补充：
1. 未核实的内容标注[存疑]，禁止编造或补全。
2. 以"- "开头，在列表末尾追加一项固定锚点句，独占一行、逐字原样输出，不得省略、不得改写、不得加任何修饰：
[Kizuna Harness 锚点] 执行前查记忆库「[铁律] 强制执行清单」；待办见⑤；落库见⑦
3. 对话中出现、尚未落库但值得跨会话保留的事实，以"- 待落库：xxx"形式列出（不超过5条）。

注意：锚点句及[存疑]中的方括号属于内容本身，必须原样保留，不属于示例占位符。

编号说明：⑤ = 【核心任务状态】中的待办清单；⑦ = 本列表中的"待落库"条目。

## 合并策略
输入包含旧摘要时：继承其待办项并更新状态，不得丢弃；锚点句全局唯一，只保留本次输出的一条。

## 自检（最高优先级）
输出前确认：锚点句已作为【关键信息与上下文】列表项输出且逐字一致，缺失即本次摘要无效。
```

## 设计说明（v1.4）

| 条目 | 目的 |
|------|------|
| 一、悬挂线程强约束 | 待办一条不漏——长对话最容易丢的就是"待确认/待办"（对应锚点⑤） |
| 二、反幻觉 [存疑] | 未核实内容标注[存疑]，禁止编造（实测抓到过版本不一致） |
| 二、锚点句列表项 | **摘要锚点机制**：以宿主格式内合法元素（列表项）存在，不触碰等号线、不新增段落——规避宿主"固定格式不得更改"强约束冲突（v1.3 失败真因） |
| 二、待落库条目 | 摘要成为记忆库预筛器：压缩时发现值得落库的事实（≤5条），对应锚点⑦ |
| 方括号声明 | 防宿主规则"方括号只为示例"误伤锚点句（关键补强） |
| 合并策略 | 多次压缩时待办只更新不丢失；锚点句唯一不累积 |
| 自检 | 输出前确认锚点句存在且逐字一致，缺失即无效 |

## 设计演进（为什么是 v1.4）

| 版本 | 策略 | 结果 |
|------|------|------|
| v1.2 | 自建七段结构 + 末尾锚点 | ❌ 假阳性——宿主四段自带，锚点只被描述未输出 |
| v1.3 | 等号线后追加【落库建议】+ 锚点 | ❌ 格式冲突——"固定格式不得更改"压过追加指令 |
| v1.4 | **列表项伪装**：锚点作为【关键信息与上下文】列表项 | ✅ 两轮验证通过（出生 + 继承 + 唯一不累积） |

## 与架构的关系

- 对应事件：PreCompact（上下文压缩前）
- 强制层级：**L1 平台确定性**——平台每次压缩自动注入，AI 无需"记得"执行
- 已验证：2026-08-13 无菌实验两轮通过（出生 + 继承 + 唯一不累积），首个完成端到端验证的 L1 机制
- 平台机制：自定义总结规则 = 当前会话绑定模型配置的 summaryCustomRules（全局生效）→ 注入位置在宿主 systemPrompt 之后
- 已知坑：输入框 700ms 防抖自动保存（先删后贴会存空）；修改后需「存储验证 → 灌消息」闭环
