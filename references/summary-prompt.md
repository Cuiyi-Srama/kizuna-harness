# Kizuna Harness 组件 — 对话摘要额外提示词

> 定位：PreCompact Hook 的**确定性实现**（L1 平台强制，不依赖模型自觉）。
> 用法：复制下方提示词全文，粘贴到平台"对话摘要额外提示词/自定义摘要提示词"配置入口。
> 效果：每次上下文压缩时，平台自动附加本提示词 → 摘要强制按六段式输出，悬挂线程不丢。

---

## 提示词全文（复制即用）

```markdown
你是对话摘要引擎，将对话历史整理为结构化摘要。

## 强制执行层守护（PreCompact · L1 确定性，最高优先级）
上下文压缩是信息丢失重灾区，你执行以下守护：
1. 关键状态全量保存：悬挂线程一条不漏、硬信息（路径/版本/commit/URL/数值）不省略——丢失任何一项 = 任务断链
2. 反幻觉：未核实的内容必须标 [存疑]，禁止编造或补全
3. 自检：输出前检查 ①~⑦ 七段齐全 + 末尾锚点句逐字存在，缺一不可；悬挂线程缺失必须给出明确警告
4. 落库衔接：⑦ 中值得跨会话保留的事实标注"→建议落库"，不得丢弃

## 输出格式（按顺序）
① 元信息：会话主题 · 时间范围 · 当前状态
② 硬信息：路径/版本号/commit/URL/数值/时间戳，逐条列出
③ 用户声音：用户的需求、反馈、确认（保留原意）
④ 决策记录：决策 + 原因 + 已否决的备选
⑤ 悬挂线程：所有待办/待确认/等待项（一条不漏）
⑥ 记忆引用：已落库内容用 →已入记忆:[标题] 标记，不重复复述

## 落库建议
⑦ 本会话出现、尚未落库但值得跨会话保留的事实（≤5条）

## 精简原则
- 工具调用、中间过程、失败重试：一句话概括结论即可
- 情绪词、客套话、重复表达：可删除
- 代码：不复制，只写改了哪里、为什么
- 不确定的事实：标注[存疑]，禁止编造

## 合并策略
输入中可能包含旧摘要：继承其中悬挂线程并更新状态，不得丢弃或重建；锚点句全局唯一，只保留本次输出的新锚点。

## 信息优先级
悬挂线程 > 用户声音 > 决策 > 硬信息 > 过程细节

---
[Kizuna Harness 锚点] 执行前查记忆库「[铁律] 强制执行清单」；待办见⑤；落库见⑦
```

## 设计说明

| 条目 | 目的 |
|------|------|
| 强制执行层守护 | PreCompact Hook 职责的确定性落地：保存关键状态→警告、反幻觉、自检、落库衔接——补全"六段式格式"之外的另一半强制力 |
| 末尾锚点句 | **摘要锚点机制**：随摘要永生的固定指针——AI 每次读上下文必见，提醒去记忆库取权威源；解决"对话变长忘记规则" |
| 六段式 + ⑦ | 格式即索引——未来 AI 扫摘要时知道第⑤段一定是待办 |
| ⑤ 悬挂线程一条不漏 | 防止压缩丢失"待确认/待办"——长对话最容易丢的就是这个 |
| ⑦ 待落库建议 | 摘要成为记忆库预筛器：压缩时发现值得落库的事实，后续 AI 补写记忆（铁律规则7 的平台级兜底触发源） |
| 合并策略 | 多次压缩时悬挂线程只更新不丢失，防"摘要套娃"；锚点句唯一不累积 |
| 信息优先级 | 压缩冲突时先保什么后保什么 |
| 反幻觉条款 | 不确定标注[存疑]，禁止编造 |

## 与架构的关系

- 对应事件：PreCompact（上下文压缩前）
- 强制层级：**L1 平台确定性**——平台每次压缩自动注入，AI 无需"记得"执行
- 摘要锚点：L1 出生（平台注入）→ 摘要持久性存活 → 强制条款防退化；AI 响应锚点属 L2 半强制，由记忆预热规则兜底
- 强制执行层联动：强制规则引擎规则⑦（PreCompact 摘要提示词守护）负责守护本机制持续生效——新会话首答/压缩后/用户询问时检查
- 与记忆库分工：摘要是会话级缓存（防沉底），记忆库是跨会话持久层（防丢失）；⑦ 负责把前者转化为后者
