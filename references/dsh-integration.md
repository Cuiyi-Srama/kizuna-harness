# Kizuna ↔ DSH 双轨集成决策基线 v1.0（社区版）
> 2026-08-14 建立。回答"是否用官方架构替换自建架构"的决策记录。

## 决策结论
**维持双轨：Kizuna 主政宿主平台（约束层），DSH 作独立实验场/参照物（执行层）。不替换。**

## 核心论证
1. **认知澄清**：自建 Harness 与官方 Harness 无真假之分，只有载体不同（宿主平台内 vs 独立进程）
2. **不可替代性**：自建 Harness 绑定宿主平台能力（记忆/世界书/平台配置注入），官方 DSH 是独立进程，物理上替代不了
3. **稳定性**：DSH v0.1 预览版官方明示兼容性破坏变更，不宜迁入生产链路
4. **场景错位**：核心场景在宿主平台内，DSH 能力（沙箱/独立执行/MCP）是增量而非替代

## 引入 DSH 后的实际变化
- 对宿主平台 Harness：零影响（平行系统）
- 新增：独立实验场（沙箱任务/对比 Agent loop）、可插拔工具链（MCP/工作流/子代理/SQLite 检索）
- 新增负担：维护（预览版迭代快）、常驻进程内存、API Key 配置、新 CLI/插件体系学习成本

## 未来切换条件（触发式评估，任一满足再议）
1. 需要脱离宿主平台的独立代码智能体（DSH 沙箱+工具链收益明确）
2. DSH 发布稳定版（1.0）且迁移收益明确
3. 需要深度使用 MCP/工作流/遥测等 DSH 独有能力且宿主平台无法提供
