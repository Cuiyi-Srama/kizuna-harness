# Harness Memory Taxonomy — 4型分类规则

> 基于 Anthropic Claude Code 源码 memory system 重建。
> v1.1: 融合经验笔记体系 — 演进标记格式 + 写入前价值判断5问

## 一、4型分类

| 类型 | 标识 | 用途 | 保守度 | 查询优先级 | 自动触发 |
|------|------|------|:--:|-----------|---------|
| user | 👤 | 用户档案、偏好、身份 | 🔴极度保守 | P1-高 | SessionStart |
| project | 📦 | 项目状态、架构、代码规范 | 🔴极度保守 | P1-高 | SessionStart(active) |
| feedback | 📝 | 错误模式、修复记录、教训 | 🟡中等 | P2-中 | PostToolUseFailure |
| reference | 📚 | 外部知识、逆向分析、文档 | 🟢宽松 | P3-低 | 按需 |

## 二、精选Agent规则

> "你正在为AI助手选择与用户查询相关的记忆。返回**最多5个**你认为明确有用的记忆。
> - 只包含你**确定**有用的记忆。不确定 → 不包括。
> - 对[user]和[project]类型**极度保守**。
> - 匹配的是**问题本身是什么**，而非表面关键词与用户身份的重叠。
> - **不重复选择**之前轮次已返回的记忆。"

**反误匹配规则**: "一个说'在做DB性能优化'的档案，与仅包含'性能'一词但不涉及该DB工作的问题**不相关**。"

**执行时机**: SessionStart运行一次 / 用户切换话题重新运行 / 同会话不重复注入

## 三、存储格式规范

### 命名规范
```
[类型] 主体 — 描述
```
类型前缀: [铁律] / [用户] / [项目] / [反馈] / [参考] / [会话] / [凭证]

### 内容规范
- 只写已发生的事实，不写推测
- 日期用绝对格式 (YYYY-MM-DD)
- 含代码时标注语言
- Token成本意识: 每条记忆正文≤2000字

### 演进标记格式 (v1.1)
feedback 型记忆正文顶部附加演进标记，用于溯源与去重：
```markdown
<!-- 演进: YYYY-MM-DD | 来源: <项目/场景/技能名> | 类型: pattern|troubleshoot|tip -->
```
- `pattern`: 可复用的工具组合/操作模式
- `troubleshoot`: 排错方案（含根因分析）
- `tip`: 平台配置/使用技巧

修正记忆使用修正标记：
```markdown
<!-- Correction: YYYY-MM-DD | was: [旧内容] | reason: [错误原因] | fix: [修正内容] -->
```

### 写入前价值判断5问 (v1.1)
写记忆前，先过5问（任一通过才值得写）：
```
1. 可复用吗？ — 不止一次有用？不是一次性操作？
2. 花了大力气吗？ — 是否费了很大劲才搞清楚？
3. 对以后有帮助吗？ — 对未来的自己或其他 AI 有帮助？
4. 已存在吗？ — 是否已存在于现有记忆/技能/包中？
5. 通用还是特定？ — 特定项目→项目快照；通用模式→独立条目
```

## 四、记忆生命周期

| 类型 | 过期时间 | 过期行为 |
|------|---------|---------|
| user | 永不过期 | 仅更新 |
| project | 项目活跃期间 | 项目结束后归档 |
| feedback | 6个月 | 合并到ironlaw后可归档 |
| reference | 永不过期 | 信息过时时更新 |
| session | 30天 | 自动归档或删除 |
| credential | 永不过期 | 凭据失效时更新 |

## 五、记忆一致性维护（v1.2 补充）

> 详见 references/memory-consistency.md（完整版）。此处只列要点。

- **单一事实源**：每类事实只在一个条目维护当前值，其他条目只写引用
- **引用去版本号**：引用铁律/规则不写版本号（升级免连锁修改）
- **规则与状态分离**：规则条目不嵌入当前状态（版本/进度放主快照）
- **过时标注**：历史快照保留，加 `⚠️[已过时] 当前以XX为准`
- **索引去计数化**：索引条目不维护数量（以实际查询为准）
- **状态变更三步走**：①更新主源 ②同步引用 ③标注旧条目
