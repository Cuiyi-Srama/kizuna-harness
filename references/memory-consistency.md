# Memory Consistency — 记忆一致性维护规范 v1.0
> 2026-08-12 建立。触发背景：记忆体检发现多处矛盾（规则版本引用分散、状态值嵌入规则、许可证新旧并存、索引统计滞后）。
> 定位：操作层规范（非铁律）。铁律是宪法，本规范是"如何保持记忆不自相矛盾"的执行细则。

## 核心原则
### 原则1：单一事实源（Single Source of Truth）
- 每类事实只在一个地方维护当前值：
  - 铁律当前版本 → `[铁律]强制执行清单`（标题唯一）
  - 项目当前版本/状态 → 该项目 `主快照` 第一行
  - 许可证/协议 → 以项目 README / 官方文档为准
- **其他条目不复制状态值**，只写"见XX条目"。
### 原则2：引用去版本号
- 引用铁律/规则时**不写版本号**（`[铁律]强制执行清单`），靠标题唯一性定位。
- 好处：v5→v6 升级时无需连锁修改所有引用处（hooks注册表、世界书、索引）。
- 例外：专有名词（如事件标题 v3.0.47）保留版本号。
### 原则3：规则与状态分离
- 规则条目只写规则（稳定），**不嵌入当前状态**（易变）。
- 状态（版本号、进度、开关）放主快照/状态条目。
- 违反示例：某项目把"当前版本"写进规则条目，版本升级后规则条目过时（已修复）。
### 原则4：过时标注（superseded 模式）
- 历史快照**保留不改**（保留历史事实），但在可见处标注：
  `⚠️[已过时] 当前以 XX 为准`
- 检索到旧条目时一眼可见指引，不会被误导。
### 原则5：索引去计数化
- 索引条目（目录/地图）**不维护条目数量**——手工统计必然滞后。
- 数量以实际查询结果为准。
## 状态变更三步走（强制）

任何"事实型"条目变更（版本号、许可证、当前状态、规则升级）必须：
1. **更新主源**：改主快照/铁律条目本身
2. **同步引用**：搜索引用该事实的所有位置（记忆、世界书、技能文件、索引），逐处更新或去版本号化
3. **标注旧条目**：历史条目加 `⚠️[已过时]` 指引，不删除
## 检查时机
- 创建/更新记忆时：新内容是否重复已有状态值？若是 → 改为引用
- 项目版本变更时：执行三步走
- 规则升级时：grep 全库引用（含世界书/技能文件）
- 定期整理时：顺带体检（对照过时条目登记表）
